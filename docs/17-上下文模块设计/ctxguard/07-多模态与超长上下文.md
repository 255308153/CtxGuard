# 07 · 多模态与超长上下文 (Multimodal & Long Context)

## 一、 多模态 Payload 安全透传

在支持 Vision 与多模态输入的场景中（如 Claude 3.5 Sonnet / GPT-4o 接收前端截图），Prompt 中包含结构复杂的 `image_url` 或 Base64 编码块：

```json
{
  "type": "image",
  "source": {"type": "base64", "media_type": "image/png", "data": "iVBORw0KGgo..."}
}
```

**CtxGuard 的防护原则**：
1. **结构识别与隔离**：文本压缩算子绝对不扫描或修改 Base64 图像块，防止损坏图像数据；
2. **多模态消息前缀锚定**：由于图像 Token 占用巨大（通常单图 800~1600 Token），一旦进入上下文历史，立即被纳入 `frozen_prefix`，防止重复计算多模态 Prefill 开销。

---

## 二、 超长上下文自适应档位降级与保护

当多轮对话累积超过 32,000 ~ 64,000 Token 时：
- `AdaptiveScheduler` 自动升级至 **Level 3 深度剪枝**；
- 激活 ONNX INT8 语义剪枝插件，针对中间历史对话进行有损高密压缩；
- 配合 `CacheGuard` 的 `cold_recompact` 机制，在长空闲后重新压实历史上下文。
