# 04 · 流式响应与拦截 (SSE Streaming)

## 一、 流式传输（SSE）在代理网关中的挑战

LLM 应用 95% 以上使用 Server-Sent Events (SSE) 流式返回响应。代理网关插在中间时，面临两大挑战：
1. **如何做到零额外延迟透传（Zero-Buffering Latency）**；
2. **如何在流式 chunks 中精准提取 Token 用量并拦截虚拟工具调用**。

---

## 二、 字节级 SSE 解析架构 (`sse.py`)

CtxGuard 在 `ctxguard/proxy/sse.py` 中实现异步流式生成器：

```text
上游云端 SSE 字节流 (data: {"choices": [{"delta": {"content": "..."}}]} 

)
       │
       ▼
[CtxGuard 异步流拦截器 async_stream_response]
       ├─ 1. 原样快速透传每个 chunk 给下游客户端 (延迟 < 0.1ms)
       ├─ 2. 实时累加 output_tokens 与 response 文本
       ├─ 3. 解析 final chunk 包含的 usage 统计 (cache_read_tokens 等)
       └─ 4. 在流结束时触发异步后台记账 (SavingsLedger.record_turn)
       │
       ▼
下游客户端 (Cursor / Claude Code / Agent SDK) 实时平滑打印打字机效果
```

---

## 三、 虚拟工具调用在流式中的短路处理

当大模型输出为 Tool Call（`finish_reason == "tool_calls"`）且调用的函数为 `ctx_expand` 时：
1. 客户端收到 tool_use 块后，会立刻发起下一轮带 tool_result 的请求；
2. 下一轮请求到达 CtxGuard 入口时，在 `VirtualToolExecutor` 处被立即截获并本地返回；
3. 整个过程对外表现为透明且无缝的实时按需展开。
