# 03 · 可逆压缩 (Reversible Dedup & Virtual Tools)

## 一、 为什么必须做「可逆」？

有损压缩的最大风险在于：**压缩时你无法预测大模型在后续步骤是否会需要被丢弃的细节**。
- 如果压缩保守 → 节省 Token 太少；
- 如果压缩激进 → 一旦丢失关键代码或数据，模型就会产生严重幻觉。

CtxGuard 的核心解法是 **CCR（Compress-Cache-Retrieve，压缩-缓存-按需取回）**：
> **平时大胆去重，把原文缓存进本地 SQLite；向模型暴露虚拟工具，模型需要时 1ms 0 Token 取回。**

---

## 二、 四步闭环机制

```text
① 首次读取大文件 / 工具输出 (10,000 Token)
   │  CtxGuard 计算 SHA-256 指纹，写入本地 SQLite 存储
   ▼
② 二次及后续重复出现时
   │  DedupCompressor 将其替换为轻量引用标记 (~15 Token)：
   │  [Ref:sha256_e4d909 | File: src/main.py | 350 lines unchanged]
   ▼
③ 网关自动注入 ctx_expand 虚拟工具
   │  在 tools 列表中声明 ctx_expand(ref_id: str)
   ▼
④ 模型需要查阅细节时调起工具
   │  CtxGuard 在网关层拦截调用，直接读取本地 SQLite，组装响应返回
   │  【上游云端大模型完全不参与这一轮往返，0 API 费用与 0 Token 开销！】
```

---

## 三、 核心实现剖析

### 1. 虚拟工具注入器 (`VirtualToolInjector`)
在 `ctxguard/core/virtual_tools/injector.py` 中，支持 OpenAI 与 Anthropic 双格式注入：

```python
OPENAI_EXPAND_TOOL = {
    "type": "function",
    "function": {
        "name": "ctx_expand",
        "description": "Decompress and retrieve full original content for a [Ref:sha256_...] reference tag.",
        "parameters": {
            "type": "object",
            "properties": {
                "ref_id": {"type": "string", "description": "The SHA-256 fingerprint from the reference tag"}
            },
            "required": ["ref_id"]
        }
    }
}
```

### 2. 本地拦截执行器 (`VirtualToolExecutor`)
在 `ctxguard/core/virtual_tools/executor.py` 中，网关在转发前检查最新消息：
- 若最新消息是模型对 `ctx_expand` 的调用，**直接本地短路（Short-Circuit）**；
- 从 `FingerprintRepository` 中根据 `ref_id` 读取原始完整文本；
- 构造标准的 `tool_result` 格式直接返回给客户端。

---

## 四、 关键深坑：Sticky-On（工具防抖动）

如果在某一轮没有发生压缩就将 `ctx_expand` 从 `tools` 列表中移除，会导致 `tools` 列表在 `[toolA, toolB]` 和 `[toolA, toolB, ctx_expand]` 之间反复跳变，从而**摧毁位于头部的前缀缓存**。

**CtxGuard 的铁律**：
> **一次开启，会话级永久保持（Sticky-On）**。只要会话中触发过一次可逆压缩，`ctx_expand` 工具在后续所有轮次始终注入，保证头部字节绝对恒定。
