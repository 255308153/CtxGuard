# 02 · 六大算子流水线

## 一、 流水线执行拓扑

CtxGuard 采用严格有序的串行管道（Pipeline）处理待压缩的消息集合（可压缩尾部活区 `compressible_suffix`）：

```text
可压缩后缀消息 (Compressible Suffix Messages)
       │
       ▼
[算子 1: DedupCompressor (SHA-256 指纹去重)]
       │  将重复的大文本/文件替换为 [Ref:sha256_...]
       ▼
[算子 2: ANSICleaner (终端控制符清洗)]
       │  剥离  颜色代码与不可见控制字符
       ▼
[算子 3: ProgressMerger (进度条合并)]
       │  折叠多帧构建/下载进度，仅保留最终状态
       ▼
[算子 4: StacktraceFolder (堆栈折叠器)]
       │  将连续重复出现的同类异常堆栈压缩为 [Repeated N times]
       ▼
[算子 5: JSONStructCompressor (JSON 结构折叠)]
       │  将同构字典数组重排为 _schema + _rows
       ▼
[算子 6: WhitespaceCleaner (空白字符压缩)]
       │  清理连续 3 个以上的空行与无意义空格
       ▼
[可选算子 7: SemanticPruner (ONNX 语义二分类剪枝)]
       │  在长上下文模式下，对低权重停用词进行安全剪枝
       ▼
输出优化后的消息集合
```

## 二、 算子设计契约与基类实现

所有算子均继承自 `BaseCompressor` 基类（`ctxguard/core/compressors/base.py`），遵循统一生命周期规范：

```python
class BaseCompressor(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """算子唯一标识名称"""
        pass

    @abstractmethod
    def is_applicable(self, context: RequestContext) -> bool:
        """根据当前配置及自适应级别判断该算子是否应该激活"""
        pass

    @abstractmethod
    def compress_text(self, text: str) -> str:
        """针对单个文本块的核心压缩算法"""
        pass

    def process(self, context: RequestContext, target_messages: List[Message]) -> None:
        """遍历消息并应用 compress_text，保护 assistant 消息不被破坏"""
        for msg in target_messages:
            if msg.role == "assistant":
                continue  # 核心保护：严禁改动 assistant 输出，防止幻觉与 prompt 模仿
            # 执行文本替换并记录应用指标
```

## 三、 Pipeline 级 Hook 扩展机制

开发者可通过装饰器向流水线注入自定义的前置与后置 Hook（例如自定义企业敏感数据脱敏、业务审计打点）：

```python
@pipeline.hook("pre_compress")
def custom_audit_hook(context: RequestContext) -> RequestContext:
    # 自定义审计逻辑或敏感词过滤
    return context
```
