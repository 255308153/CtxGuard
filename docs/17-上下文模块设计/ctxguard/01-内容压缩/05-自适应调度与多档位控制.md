# 05 · 自适应调度与多档位控制

## 一、 为什么需要自适应档位？

不同上下文长度对压缩的敏感度和容忍度完全不同：
- **短上下文（< 4,000 Token）**：Token 空间充裕，应尽量减少干预，追求 100% 原始保真度；
- **中等上下文（4,000 ~ 32,000 Token）**：触发纯规则清洗与结构折叠，兼顾效率与安全；
- **超长上下文（> 32,000 Token）**：面临上下文窗口溢出与高额成本，需激活更激进的语义剪枝。

---

## 二、 四级自适应档位（Levels）设计

在 `ctxguard/core/adaptive_scheduler.py` 中定义了四个自适应档位：

| 档位 | 上下文 Token 门限 | 激活算子与策略 | 预期压缩率 | 延迟开销 |
|---|---|---|---|---|
| **Level 0 (PassThrough)** | `< 2,000 Token` | 仅执行去重指纹建立，不修改任何正文 | 100% (不压缩) | < 0.2ms |
| **Level 1 (Light Heuristic)** | `2,000 ~ 8,000 Token` | ANSI 清洗 + 进度条合并 + 空白压缩 | 85% ~ 95% | < 0.5ms |
| **Level 2 (Deep Structural)** | `8,000 ~ 32,000 Token` | + SHA-256 指纹替换 + JSON Schema 折叠 + 堆栈折叠 | 40% ~ 70% | < 1.5ms |
| **Level 3 (Semantic Prune)** | `> 32,000 Token` | + ONNX INT8 微型双向打分剪枝插件 | 30% ~ 50% | < 5.0ms |

## 三、 动态调节流水线上下文

```python
class AdaptiveScheduler:
    def tune_pipeline_context(self, context: RequestContext) -> None:
        token_len = context.original_tokens
        if token_len < self.config.level0_threshold:
            context.active_level = 0
        elif token_len < self.config.level1_threshold:
            context.active_level = 1
        elif token_len < self.config.level2_threshold:
            context.active_level = 2
        else:
            context.active_level = 3
```

流水线中各个算子在 `is_applicable(context)` 中检查当前 `context.active_level`，实现零人工介入的完全自适应调度。
