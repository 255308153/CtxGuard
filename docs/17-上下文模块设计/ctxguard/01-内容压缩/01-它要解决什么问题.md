# 01 · 它要解决什么问题

## 一、 Agent 运行时的 Token 膨胀灾难

在 Coding Agent（如 Cursor / Claude Code）、多轮数据分析和自动化工作流中，上下文体积会迅速膨胀到数十万 Token。排查发现，大部分消耗并非来自用户的提问或模型的推理，而是**被高度冗余且无价值的噪音文本填满**：

```text
典型 Agent 上下文 Token 分布构成：
┌────────────────────────────────────────────────────────────┐
│ ■ 重复读取的代码文件全文 (40%~60%)                          │
│ ■ 工具返回的同构 JSON 大数组 (20%~30%)                      │
│ ■ 终端构建 ANSI 颜色码、无意义进度条与重复堆栈 (10%~15%)    │
│ □ 真正的用户指令与有效核心代码逻辑 (仅占 10%~15%)           │
└────────────────────────────────────────────────────────────┘
```

---

## 二、 三大典型冗余案例剖析

### 1. 痛点一：重复文件读取（Duplicate File Contents）
Agent 在第 1 轮读取了 `src/server.py`（1000 行，约 5,000 Token）。在第 3 轮、第 5 轮为了排查问题又重复执行了 `read_file("src/server.py")`。
- **后果**：同一份 5,000 Token 的代码在上下文中重复出现了 3 次，白白浪费 10,000+ Token。

### 2. 痛点二：JSON 同构对象数组的 Key 膨胀
数据库查询或 API 工具返回 100 条记录时，每一个 JSON 对象都完整携带了冗余的键名：
```json
[
  {"user_id": 1001, "username": "alice", "email": "alice@corp.com", "status": "active"},
  {"user_id": 1002, "username": "bob", "email": "bob@corp.com", "status": "active"},
  ... (重复 100 次相同的键名)
]
```
- **后果**：键名占据了超过 55% 的字符开销，不仅浪费 Token，而且稀释了模型的注意力。

### 3. 痛点三：终端 ANSI 颜色转义与进度条轰炸
执行 `npm install` 或 `cargo build` 时，终端输出包含海量 ANSI 颜色码（如 `[32m`）以及不断刷屏的进度条（如 `[=>  ] 10%  [==> ] 20%  ...`）。
- **后果**：几百行无效的终端控制字符塞进 Prompt，除了浪费钱，还会诱发模型输出乱码或格式错误。

---

## 三、 CtxGuard 的解决策略

针对上述问题，CtxGuard 设计了**多层次结构化压缩流水线**：
1. 用 **SHA-256 指纹替换** 根治重复文件冗余（结合 `ctx_expand` 可逆展开）；
2. 用 **Schema+Rows 矩阵重排** 根治 JSON 键名膨胀；
3. 用 **流式正则折叠器** 根治 ANSI 转义码与进度条噪音。
