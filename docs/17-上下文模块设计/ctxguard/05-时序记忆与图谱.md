# 05 · 时序记忆与图谱 (Personal Knowledge Graph)

## 一、 为什么放弃重型向量库，选择 SQLite + FTS5 + 图谱？

对于单机开发或中小团队 Agent 而言，维护独立向量库（如 Milvus / Qdrant）成本极高且缺乏时序演化能力。

CtxGuard 在 `ctxguard/storage/repository_graph.py` 中实现了一个**单文件、零运维的时序知识图谱存储（SQLiteGraphStore）**：
- **FTS5 BM25 检索**：精准匹配代码符号、函数名与专业实体；
- **2 跳 BFS 子图检索**：快速拉取与当前任务相关的实体上下文网络；
- **事实版本演化链（Supersession Chain）**：记录用户偏好与技术事实的时序更迭。

---

## 二、 核心机制解析

### 1. 事实永不删除，只被版本覆盖 (Supersession Chain)
当用户提出新偏好（例如“以后改用 pytest，不要用 unittest”）时：
- 旧实体并不执行 `DELETE`，而是更新其 `valid_until = NOW()`，并将 `superseded_by` 指向新实体 ID；
- 新实体的 `supersedes` 关联旧实体，`valid_until = NULL`；
- 查询时默认过滤 `valid_until IS NULL`，实现历史可追溯且当前视图纯净。

### 2. 时序指数衰减打分 (`RecencyBoostRanker`)
结合 BM25 文本相关性得分与时间衰减因子：

$$	ext{Score}(E) = 	ext{BM25\_Score}(E) 	imes e^{-\lambda \cdot \Delta t_{	ext{days}}}$$

默认衰减系数 $\lambda = 0.05$（14 天前的记忆权重衰减约为 50%），优先激活新鲜知识。

## 三、 深度架构解析：事实记忆 (Memory) 的提取与召回哲学

### 1. 事实记忆 (Memory) vs 避坑规则 (Learned Rules) 的核心边界

在工业级 Agent 上下文治理中，必须严格区分两类资产：
- **事实记忆 (Memory)**：描述客观实体与用户偏好（“是什么”），在**在线交互中通过虚拟工具 (`memory_save`) 或轻量被动流量提取**，存入知识图谱数据库，按需动态召回；
- **避坑规则 (Learned Rules)**：描述工程规范与踩坑指南（“怎么做 / 禁止怎么做”），在**任务结束后通过离线 Digest 进行全局 LLM 因果复盘**，写入规则文件常驻。

| 维度 |  事实记忆 (Memory) |  避坑规则 (Learned Rules) |
| :--- | :--- | :--- |
| **触发时机** | **在线对话时**（0 额外 LLM 调用，Tool Call 顺便带回） | **离线复盘时**（全局仅调用 1 次独立 LLM） |
| **存放形式** | **本地图谱数据库** (`.ctxguard.db`) | **项目规则文件** (`.cursorrules` / `CLAUDE.local.md`) |
| **生效机制** | 混合相关度打分后 **动态追加在当前轮 User 消息尾部** | 作为 **System/Project 上下文常驻** |

### 2. 缓存安全召回 (Cache-Safe Injection)
- **绝对保护前缀**：坚决禁止将召回内容塞入 System Prompt 开头（会彻底摧毁云端 KV Cache）；
- **动态后缀注入**：仅在当前轮用户提问末尾追加精简格式的 `[User Context & Preferences]` 事实块；
- **历史幂等清洗**：在多轮交互中，自动剥离历史消息里的旧记忆与旧协议标签，确保上下文 100% 干净且前缀字节流 SHA-256 零漂移。
