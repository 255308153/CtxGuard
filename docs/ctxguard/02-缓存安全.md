# 02 · 缓存安全 (Cache Guard)

> **第一性原理**：压缩只是副产品，真正要保的是前缀缓存（Prompt Cache）。

---

## 一、 什么是 Prompt Cache（前缀缓存）

主流大模型服务商（Anthropic Claude、DeepSeek、OpenAI）为了降低推理成本和 TTFT 首字延迟，提供了 **Prompt Caching（前缀缓存）** 技术。

```text
位置：     [1]     [2]     [3]     [4]     [5]     [6]     [7]
内容：   [System] [Rule1] [Rule2] [Tool1] [User1] [Asst1] [User2]
```

**供应商的缓存比对规则**：
- 必须**从第 1 个 Token 开始从前向后逐字节严格完全匹配**；
- 只要匹配成功，命中的前缀部分享受 **90% 价格减免（1 折）**；
- **只要你在中间修改了任意 1 个字符（哪怕是一个空格或标点），从那个字符往后的所有缓存全部作废！**

```text
第 1 轮发出： [System 2000][Tools 1000][User1 500]       (总计 3500 Token)
计费：3500 Token 全价

第 2 轮发出： [System 2000][Tools 1000][User1 500][Asst1 400][User2 300]
比对：前 3500 Token 完全一致 → 命中 3500 Token
计费：3500 × 0.1 (折后仅 350) + 700 (新增全价) = 1,050 计费 Token

此时如果你在第 2 轮盲目把 User1 压了一下 (500 → 200)：
第 2 轮发出： [System 2000][Tools 1000][User1' 200][Asst1 400][User2 300]
比对：前 3000 Token 对上，到 User1' 发生变化 → 后面全部 Miss
计费：3000 × 0.1 (300) + 900 (全价重算) = 1,200 计费 Token  (比不压还贵！)
```

## 二、 经济套利仲裁公式 (Economic Arbitrator)

为了避免“省了 Token 却赔了钱”，CtxGuard 在 `ctxguard/core/guards/cache_guard.py` 中内置了严密的**经济套利仲裁器**：

$$\text{savings\_fraction} = \frac{\text{raw\_tokens} - \text{compressed\_tokens}}{\text{raw\_tokens}}$$

$$\text{Break-Even 判据} : \text{savings\_fraction} > \text{provider\_read\_discount}$$

| 服务商 | 官方读取折扣 (Discount) | 允许打破缓存的压缩节省率门槛 |
|---|---|---|
| **Anthropic Claude** | 90% (0.90) | 压缩节省率必须 **> 90%** 否则严禁改动已缓存前缀 |
| **DeepSeek V3** | 90% (0.90) | 压缩节省率必须 **> 90%** 否则严禁改动已缓存前缀 |
| **OpenAI GPT-4o** | 50% (0.50) | 压缩节省率必须 **> 50%** |

## 三、 CtxGuard 的四大缓存保全核心机制

### 1. 动态 Token 边界反向映射 (`compute_frozen_boundary`)
上游返回的响应中仅包含 `cache_read_input_tokens` 和 `cache_creation_input_tokens`，不直接告诉网关“具体缓存到第几条消息”。
CtxGuard 从第 0 条消息开始正向累加 Token 数，精确反推出 `frozen_message_count`，将消息分为：
- **[Frozen Prefix] 冻结前缀区**：绝对禁止任何算子介入；
- **[Compressible Suffix] 活区尾部**：新到的用户指令与工具返回值，可自由压缩。

### 2. 覆盖式前缀重放 (`Overlay Cached Prefix`)
不同序列化库或 Python 字典可能在 key 顺序、空格、浮点数精度上产生微小抖动。CtxGuard 缓存上一轮实际转发的原始对象，并在新一轮中直接覆盖重放冻结前缀，保证 SHA-256 级绝对一致。

### 3. 非语义字段清洗 (`_NON_SEMANTIC_KEYS`)
在比对前缀稳定性时，自动剥离诸如 `cache_control`、`index`、`system_fingerprint` 等平台非语义浮动字段，杜绝误判。

### 4. 冷重压缩与 TTL 判定 (`should_cold_recompact`)
Anthropic 的 Prompt Cache 生命周期默认约 5 分钟（300 秒）。若会话空闲时间 `idle_seconds > cache_ttl_seconds`，云端缓存已自然过期，此时 CtxGuard 会自动触发全量深度重压缩（Cold Recompact），重新建立紧凑的新前缀。
