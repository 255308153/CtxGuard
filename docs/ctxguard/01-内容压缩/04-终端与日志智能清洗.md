# 04 · 终端与日志智能清洗

## 一、 ANSI 颜色转义码清洗 (`ANSICleaner`)

开发工具输出中常包含大量终端颜色与格式控制字符：
```python
# ctxguard/core/compressors/ansi_cleaner.py
ANSI_REGEX = re.compile(r"\x1b\[[0-9;]*[a-zA-Z]|\x1b\([a-zA-Z]")
```
- **示例**：`\x1b[32m Test passed\x1b[0m` → ` Test passed`
- **收益**：彻底消除无意义控制符，防止模型因解析未知转义字符而产生格式乱码。

---

## 二、 进度条智能合并 (`ProgressMerger`)

构建或包管理工具（`pip`, `npm`, `cargo`, `docker`）在流式输出中会不断产生进度覆盖帧：
```text
[===>                 ] 15%
[========>            ] 40%
[====================>] 100% Done
```
`ProgressMerger`（`ctxguard/core/compressors/progress_merger.py`）通过正则匹配多行连续的进度条模式，**仅保留最终完成帧**，将其余过渡帧剔除。

---

## 三、 重复异常堆栈折叠 (`StacktraceFolder`)

在循环重试或并发请求失败时，同一 Python/Java 报错堆栈往往连续出现数十次：

```text
【折叠前 (重复 10 次相同 Traceback)】
Traceback (most recent call last):
  File "network.py", line 88, in fetch
    ConnectionRefusedError: [Errno 61] Connection refused
... (相同内容重复 10 遍)

【折叠后】
Traceback (most recent call last):
  File "network.py", line 88, in fetch
    ConnectionRefusedError: [Errno 61] Connection refused
[CtxGuard: Identical stacktrace repeated 9 times folded]
```

- **首帧完整保留（First Frame Preserved）**：严格保留第 1 次异常的完整文件名、行号与局部变量，只折叠后续完全相同的重复堆栈，保证模型 Debug 能力 100% 不受损。
