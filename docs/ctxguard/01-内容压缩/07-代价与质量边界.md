# 07 · 代价与质量边界

## 一、 压缩的两难困境

在上下文压缩工程中，存在经典的“压缩率与信息保真”平衡：

```text
          极致压缩率 (节省 90% Token)
                    ▲
                   / \
                  /   \
                 /     \
  语法/逻辑安全性 ◄─────► 低网关处理延迟 (<3ms)
```

如果盲目追求过高压缩率：
1. **破坏代码语法**：丢掉闭合括号或缩进，导致代码解析错误；
2. **模型不知道自己丢失了信息**：看到残缺内容强行推理，引发严重幻觉；
3. **破坏厂商 Prompt Cache**：改动静态前缀，导致账单反增。

---

## 二、 CtxGuard 的四大质量安全红线

为了坚守质量底线，CtxGuard 确立了四条不可逾越的红线：

### 1. 助手消息永不动（Assistant Messages Immutability）
流水线对 `role == "assistant"` 的消息绝对不做任何改动。
- **原因**：如果修改了 Assistant 的历史发言，会导致模型在后续轮次模仿被破坏的语法结构，或者引起 EOS 终止符提前触发。

### 2. 代码与堆栈可逆保真
针对长代码文件，优先使用 SHA-256 去重与 `ctx_expand` 虚拟工具，**绝不进行有损语义摘要**。

### 3. 经济套利安全门禁
只有在压缩净节省额度显著超过损失的云端 Prompt Cache 读取折扣时，才允许对可疑边界执行操作。

### 4. 异常自动降级回滚（Fallback to Original）
任何算子若在执行中发生解析异常或 Token 估算反增，立即静默回滚至原始文本，确保 100% 请求成功率。
