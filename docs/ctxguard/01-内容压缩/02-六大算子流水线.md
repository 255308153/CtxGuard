# 02 · 算子执行流水线 (Pipeline)

## 一、 算子执行流水线拓扑

在 `ctxguard/core/pipeline.py` 中，`CompressionPipeline` 按严格顺序组织并执行各个算子：

```text
待压缩后缀消息 (Compressible Suffix)
       │
       ▼
[1. GitDiffCompressor]     ──► 折叠 Unified Diff 大段未变动上下文行 (保留增删改与锚点)
       ▼
[2. DedupCompressor]       ──► 基于 SHA-256 指纹替换历史重复文件与工具输出 (LRU 淘汰)
       ▼
[3. ASTCodeCompressor]     ──► AST 语法树智能折叠大文件实现体
       ▼
[4. ANSICleaner]           ──► 正则剥离 \x1b 终端颜色代码与不可见控制字符
       ▼
[5. ProgressMerger]        ──► 折叠多帧构建/下载进度条，仅保留最终完成帧
       ▼
[6. StacktraceFolder]      ──► 将连续重复出现的同类异常堆栈折叠为 [Repeated N times]
       ▼
[7. JSONStructCompressor]  ──► 将同构字典数组重排为 _schema 表头 + _rows 矩阵
       ▼
[8. WhitespaceCleaner]     ──► 清理连续 3 个以上的空行与行尾无意义空格
       ▼
[可选 9. SemanticPruner]   ──► 超长上下文下通过 ONNX INT8 微型双向编码器剪枝
       ▼
[10. OutputShaper]         ──► Byte-Stable 注入输出约束哨兵，消除模型客套话
       │
       ▼
输出优化后的消息集合
```

## 二、 核心抽象：`BaseCompressor` 契约

所有压缩算子均继承自 `ctxguard/core/compressors/base.py`：

```python
class BaseCompressor(ABC):
    @property
    @abstractmethod
    def name(self) -> str:
        """算子唯一名称"""
        pass

    @abstractmethod
    def is_applicable(self, context: RequestContext) -> bool:
        """根据当前配置与自适应等级判断算子是否激活"""
        pass

    @abstractmethod
    def compress_text(self, text: str) -> str:
        """核心文本清洗与转换逻辑"""
        pass

    def process(self, context: RequestContext, target_messages: List[Message]) -> None:
        """遍历消息并应用，严格保护 role == 'assistant' 的消息不可变"""
        for msg in target_messages:
            if msg.role == "assistant":
                continue  # 铁律：永不动 Assistant 消息，防止 Prompt 模仿
            # 执行文本替换
```

## 三、 回滚与 Hook 扩展机制

1. **原子回滚副本（Atomic Copy Fallback）**：
   在进入算子流水线前，`pipeline.py` 保存了后缀消息的深拷贝（`orig_suffix_copies`）。若后续经济套利检查判定压缩收益低于云端 Prompt Cache 读取折扣，流水线立即**无损回滚**至原始副本；
2. **装饰器 Hook**：支持通过 `@pipeline.hook("pre_compress")` 和 `@pipeline.hook("post_compress")` 插入自定义企业级脱敏或业务审计逻辑。
