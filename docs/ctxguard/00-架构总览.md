# 00 · 架构总览

## 一、 CtxGuard 是什么

`CtxGuard`（Context Guard —— 上下文守护者）是一个高性能、超轻量级的 **LLM 上下文智能优化与安全守护反向代理网关**。
它插在客户端（Cursor、Claude Code、Python Agent SDK）与云端大模型 API（Anthropic Claude、DeepSeek、OpenAI）之间，实现无感拦截、Prompt 结构化优化与成本削减。

```text
客户端 (Cursor / Claude Code / Agent SDK)
       │  发送标准 HTTP 请求 (包含完整 system, messages, tools)
       ▼
┌──────────────────────────────────────────────────────────┐
│  CtxGuard 本地代理 (运行于 127.0.0.1:8787，开销 < 3ms)          │
│  ① 协议归一化 → ② 缓存冻结分区 → ③ 指纹去重 → ④ 结构压缩      │
└──────────────────────────────────────────────────────────┘
       │  转发经过极致压缩且严格前缀对齐的 Payload
       ▼
云端大模型 API (Anthropic Claude 3.5 / DeepSeek V3 / OpenAI GPT-4o)
```

---

## 二、 核心设计约束（Three Ultra-Lightweight Principles）

1. **0 外部重型服务依赖**：绝不依赖 Docker、Redis、PostgreSQL、Milvus。全系统仅需单文件内置 `sqlite3`；
2. **0 庞大深度学习框架**：默认核心采用纯算法、正则与 AST 结构折叠；可选语义剪枝插件仅依赖 `onnxruntime-cpu`（仅 30MB），彻底告别 PyTorch/Transformers；
3. **极致低延迟透传**：采用 Rust 编写的 `orjson`（C/SIMD 指令加速），网关层增加的处理延迟压低在 **< 3ms（实测基准平均 1.08ms）**。

## 三、 核心请求生命周期（10 步链路）

在 `ctxguard/core/pipeline.py` 与 `ctxguard/proxy/server.py` 中，请求依次流经以下 10 步处理：

```text
① 客户端请求入站 (POST /v1/chat/completions 或 /v1/messages)
       ↓
② 协议归一化 (Adapter)
       → 将 OpenAI / Anthropic 格式转为统一内部对象 NormalizedRequest
       ↓
③ 初始 Token 评估与自适应档位调度 (AdaptiveScheduler)
       → 估算 Prompt 大小，动态分配 Level 0 ~ Level 3 压缩等级
       ↓
④ 虚拟工具本地短路拦截 (VirtualToolExecutor)
       → 若检测到模型请求执行 ctx_expand，本地直查 SQLite 返回，0ms / 0 上游 Token
       ↓
⑤ Prompt Cache 动态分区 (CacheGuard)
       → 依据历史命中反算边界，切分为 [Frozen Prefix 冻结前缀] 与 [Compressible Suffix 活区尾部]
       ↓
⑥ 活区可逆去重与结构化压缩 (Compression Pipeline)
       ├─ DedupCompressor: 重复文件替换为 [Ref:sha256_...]
       ├─ ANSICleaner: 正则清除终端颜色转义码
       ├─ ProgressMerger: 进度条合并保留最终帧
       ├─ StacktraceFolder: 重复异常堆栈折叠为 [Repeated N times]
       ├─ JSONStructCompressor: 同构字典数组提取 _schema + _rows
       └─ WhitespaceCleaner: 多余连续空行与格式压缩
       ↓
⑦ 经济套利仲裁 (Economic Arbitrator)
       → 若压缩节省收益低于云端 Prompt Cache 读取折扣，自动回退原文保全缓存
       ↓
⑧ 工具注入与 Cache 断点标记 (VirtualToolInjector & CacheGuard)
       ├─ 注入 ctx_expand 工具定义 (Sticky-On 保持稳定)
       └─ 针对 Anthropic 自动注入 cache_control: {"type": "ephemeral"}
       ↓
⑨ 转发上游云端 API (Upstream Client)
       → 基于 httpx 异步连接池与 orjson 快速序列化转发
       ↓
⑩ SSE 流式解析、响应透传与账本落盘 (SSE Streamer & SavingsLedger)
       → 拦截流式输出，实时记录原始/压缩/缓存命中 Token 与资金节省明细入 SQLite
```

## 四、 核心代码架构映射

```text
ctxguard/
├── proxy/               # 反向代理与协议适配
│   ├── server.py        # FastAPI / Starlette 异步高性能主服务
│   ├── router.py        # OpenAI / Anthropic 双向路由分发
│   ├── upstream.py      # 上游长连接池与转发客户端
│   ├── sse.py           # SSE 流式解析与 Token 实时记账
│   └── adapters/        # OpenAI / Anthropic 双向协议归一化
├── core/                # 上下文核心中枢
│   ├── pipeline.py      # 压缩流水线控制器
│   ├── context.py       # NormalizedRequest / RequestContext 核心数据结构
│   ├── adaptive_scheduler.py # 自适应多档位调度器 (L0~L3)
│   ├── semantic_cache.py     # 会话与全局语义缓存
│   ├── guards/          # Prompt Cache 守护者 (cache_guard.py)
│   ├── compressors/     # 六大结构化压缩算子 (dedup, json, ansi, stack, etc.)
│   └── virtual_tools/   # 虚拟工具注入与本地短路执行器
├── storage/             # 单文件嵌入式存储
│   ├── db.py            # SQLite 连接池与 WAL 模式管理
│   ├── repository_fingerprint.py  # SHA-256 去重指纹库
│   ├── repository_graph.py        # SQLite + FTS5 时序实体知识图谱
│   └── savings_ledger.py          # 双向记账本 (Token 与资金节省)
├── learn/               # 离线自进化引擎
│   ├── loop_detector.py # 死循环与重复报错挖掘
│   ├── causality_extractor.py     # 因果转折点提取
│   └── atomic_writer.py # 标记块隔离规则落盘写入器
└── plugins/onnx/        # 可选 INT8 双向编码器语义剪枝插件
```
