# 10 · 接入方式与多协议适配

## 一、 零侵入透明反向代理接入

CtxGuard 最大优势在于**零业务代码侵入**。任何支持配置 `base_url` 的客户端或框架均可秒级接入。

### 1. Claude Code 接入
```bash
# 启动 CtxGuard 守护网关
ctxguard start

# 设置环境变量将 Claude Code 指向本地代理
export ANTHROPIC_BASE_URL="http://127.0.0.1:8787"
claude
```

### 2. Pi Agent + Pi-Web 接入 (主流推荐)
在 `pi agent` 配置文件或环境中设置：
```bash
export OPENAI_BASE_URL="http://127.0.0.1:8787/v1"
export ANTHROPIC_BASE_URL="http://127.0.0.1:8787"
```
启动 `pi-web`（端口 30141）后，所有发出的 Agent 动作流、代码审查及工具调用，均由 CtxGuard 网关自动完成 Prompt Cache 防抖、冗余清洗与知识图谱记忆召回。

### 3. Cursor / VSCode 接入
在 Cursor 设置中：
- 将 OpenAI / Anthropic Base URL 配置为 `http://127.0.0.1:8787/v1`；
- API Key 填入任意字符串（或由 CtxGuard 在 `ctxguard.yaml` 中统一向上游注入）。

### 4. GPT / OpenAI 系列官方生态与 SDK 接入
针对 ChatGPT / GPT-4o / o1 / o3-mini 及兼容生态：
```python
from openai import OpenAI

# 仅需将 base_url 指向 CtxGuard
client = OpenAI(
    base_url="http://127.0.0.1:8787/v1",
    api_key="sk-upstream-openai-key",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Analyze codebase..."}]
)
```

## 二、 双向协议适配器架构 (`ctxguard/proxy/adapters/`)

CtxGuard 内置适配器模式（Adapter Pattern），无缝处理格式差异：
- `OpenAIAdapter`：处理 `/v1/chat/completions`、`functions` / `tool_calls`；
- `AnthropicAdapter`：处理 `/v1/messages`、`system` 顶层字段、`tool_use` / `tool_result` content blocks 以及 `cache_control` 断点。

---

## 三、 开放可扩展插件接口 (Extensible SPI / Plugin Interface)

CtxGuard 提供了高度解耦的开放接口架构，便于未来横向扩展新模型提供商与自定义压缩算子：

1. **自定义协议适配器 (`BaseProtocolAdapter`)**：
   - 继承 `ctxguard.proxy.adapters.base.BaseAdapter`；
   - 实现 `normalize_request(body)` 与 `denormalize_response(resp)`，即可零侵入支持 Gemini / Ollama / Mistral / DeepSeek 专有协议。

2. **自定义压缩算子插件 (`BaseCompressor`)**：
   - 继承 `ctxguard.core.compressors.base.BaseCompressor`；
   - 实现 `compress_message(msg: Message) -> Message`，即可无缝挂载特定语言（如 C++/Rust AST）或特定业务格式的专用压缩清洗插件。
